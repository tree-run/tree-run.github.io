## 常规函数

`read`（读什么（从哪儿读），写到哪，写多少）

`write`（往哪写，写什么（从哪写），写多少）

`execve`（binsh，argv（0），envp（0））

`mencpy`（拷贝到哪里，从哪里开始拷贝，拷贝多少字节）`不检查长度`

`fgets`（写到哪， 最多写多长，从哪读）

`strcspn`（从哪开始，到哪结束） 统计不含结尾的字符个数

`strncmp`（比较量1，比较量2，最多比较字符个数） 全相等返回0

`atoi`（const char *str）将字符转为整数形式，如 '1' →1

`fwrite`（数据从哪来，每个元素多少字节，几个元素，写到哪）

`fputc`（要写出的字符，目标文件流）

`memset`（起始内存地址，要填充的值，要填充的字节数） 内存填充函数，把一块内存的每个字节都设成同一个值

`getrandom`（指向接收随机字节的缓冲区，请求的随机字节数，控制行为的标志位可以是0） 内核真随机，不能预测

fmtstr_payload(8, {printf_got: backdoor})

write_size='byte'    # 默认，用 %hhn 写 1 字节；小地址、后门地址

qword大概率是got表，标thunk的大概率是plt

`rax`的取值:

- 0 是read
- 1 是write

## 分配内存

### mmap

`mmap`（建议的映射起始地址，映射的字节数，内存保护权限，内存的共享属性和特殊行为，指定要映射的文件，文件偏移量）
原型：

> void mmap(void*addr,size_t len,int prot,int flags,int fd,off_t offset);

成功时返回映射区域的起始地址指针

mmap 并不会立即分配物理内存。它只是在进程的虚拟地址空间中划出一块区域，并建立与文件的关联（如果是文件映射）。当程序首次访问这块内存时，会触发一个缺页异常，此时内核才会真正地从磁盘加载文件内容或分配物理内存页。

prot权限位计算：

```python
define PROT_READ     0x1   # 二进制 001  可读
define PROT_WRITE    0x2   # 二进制 010  可写
define PROT_EXEC     0x4   # 二进制 100  可执行
从而有:
0x1 | 0x2 = 0x3 → 可读 + 可写(rw)
0x1 | 0x4 = 0x5 → 可读 + 可执行(rx)
0x1 | 0x2 | 0x4 = 0x7 → 可读 + 可写 + 可执行

```

### malloc

`malloc` （要分配的字节数）

原型：void *malloc(size_t size)

返回值：

- 成功：返回指向分配内存的指针，内存内容未初始化（可能是垃圾值）。

- 失败：返回 NULL，并设置 errno = ENOMEM。

## IDA

程序发布的时候删掉了原来 C 语言的变量名、函数名，IDA 不知道它本来叫啥，就用【前缀 + 内存地址】给它起名字，方便你看汇编、跳转分析

例如：

| 名称前缀 | 含义 | 位置 |
| ---- | ---- | ---- |
| sub_ | 函数（子程序） | 代码段 .text |
| loc_ | 跳转标签（分支位置） | 代码段 .text |
| byte_ | 1字节全局变量 | 数据段 |
| word_ | 2字节全局变量 | 数据段 |
| dword_ | 4字节全局变量 | 数据段 |
| qword_ | 8字节全局变量 | 数据段 |
| off_ | 指针/地址偏移 | 数据段 |
| asc_ / aXXX | ASCII字符串 | .rodata / 数据段 |
| unk_ | IDA无法识别的原始字节 | 数据段 |
| flt_ | float单精度浮点数（4字节） | 数据段 |
| dbl_ | double双精度浮点数（8字节） | 数据段 |
| stru_ | 结构体 | 类型定义（不占运行内存） |
| var_ | 栈上局部变量 | 函数栈 stack |
| arg_ | 函数入参 | 函数栈 stack |
| locret_ | ret返回指令位置标签 | 代码段 .text |
| align_ | 内存对齐填充 | 对应段内填充 |
| jpt_ | 跳转表（switch-case） | 代码段/数据段 |
