### strcpy

>原型：`strcpy(dest, src)`

- 一直复制到 `src` 的 `\0` 为止，**完全不检查 `dest` 有多大**
    
- 只要 `src` 比 `dest` 长，就是**缓冲区溢出**，经典 Pwn 漏洞来源

### strncpy

`strncpy`（到哪里，从哪来，多少）

> 原型：char *strncpy(char *dest, const char *src, size_t n);

strncpy() 函数从源 src 所指的内存地址的起始位置开始复制 n 个字节到 目标 dest 所指的内存地址的起始位置中

- 最多复制 `n` 个字节，不会写超过 `dest` 容量（前提是你 `n` 传对了）。
    
- 但它有两个经典坑：
    
    1. **不保证 `\0` 结尾**：如果 `src` 长度 ≥ `n`，复制完 `n` 个字节后**不会补 `\0`**。后续用 `%s` 打印或 `strlen` 就会越界读，造成信息泄露甚至崩溃。
    
    2. **可能用 `\0` 填充**：如果 `src` 比 `n` 短，它会把 `dest` 剩余空间全填 `\0`，性能上有点浪费。

所以 `strncpy` 的正确用法通常是：

```c
strncpy(dest, src, sizeof(dest) - 1);
dest[sizeof(dest) - 1] = '\0';
```

### memcpy

`memcpy`（复制到哪里，从哪儿来，多少字节）

>原型：void *memcpy(void *dest, const void *src, size_t n);

从 `src` 指向的内存开始，复制 `n` 个**字节**到 `dest` 指向的内存，返回 `dest`

`memcpy` 很强大，但使用时有几个必须留意的点：

1. **按字节复制，不关心类型**：它只负责搬运 `n` 个字节，不管这些字节代表的是整数、字符还是结构体。这带来了极大的灵活性，可以复制任何类型的数据

2. **不处理 `\0` 结束符**：与 `strcpy` 不同，`memcpy` 不会在遇到 `\0` 时停止，它严格根据你给定的 `n` 值来复制。因此，它很适合复制包含 `\0` 的二进制数据（如图片、音频数据）或结构体
    
3. **最大风险：内存区域重叠**：**如果 `dest` 和 `src` 指向的内存区域有重叠，`memcpy` 的行为是未定义的**，结果可能因平台而异，导致数据损坏。遇到这种情况，必须改用 **`memmove`** 函数，它能安全地处理内存重叠的复制
    
4. **空间要足够**：你必须确保 `dest` 指向的内存空间至少有 `n` 个字节，否则会发生缓冲区溢出，这是常见的安全漏洞来源。

#### 整数溢出示例 —— 整数转换

```c
char buf[80]; 
void vulnerable() {
	int len = read_int_from_network(); 
	char *p = read_string_from_network(); 
	if (len > 80) { 
		error("length too large: bad dog, no cookie for you!"); 
		return; 
	} 
	memcpy(buf, p, len); 
}
```

*这个例子的问题在于，如果攻击者给 len 赋于了一个负数，则可以绕过 if 语 句的检测，而执行到 memcpy() 的时候，由于第三个参数是 size_t 类型，负 数 len 会被转换为一个无符号整型，它可能是一个非常大的正数，从而复制了大 量的内容到 buf 中，引发了缓冲区溢出*

### strtol

`strtol`（要转换的字符串，指向“第一个无法转换的字符”的指针，进制，`10` 表示十进制，`16` 表示十六进制，`0` 表示自动识别）

### strlen

> 原型：size_t strlen(const char *s);

- **`s`**：以 `\0` 结尾的字符串指针。
- **返回值**：`size_t`，即字符个数，**不含结尾的 `\0`**

`strlen` 是 C 标准库里的**字符串长度计算函数**，全称 “string length”。作用是**从给定地址开始往后数，直到遇到第一个 `\0` 为止，返回数到的字符个数（不含 `\0`）**

`strlen` 相关的漏洞常见于**无 `\0` 结尾的缓冲区**导致越界读/信息泄露；`strlen(s) - 1` 这类下溢绕过长度校验；以及用 `strlen` 算剩余空间时算错导致后续 `strcat`/`memcpy` 溢出

#### 整数溢出示例

源码：

```c
#include <stdio.h>
#include 
void validate_passwd(char *passwd) { 
	char passwd_buf[11]; 
	unsigned char passwd_len = strlen(passwd); 
	if(passwd_len >= 4 && passwd_len <= 8) { 
		printf("good!\n"); 
		strcpy(passwd_buf, passwd); 
	} else { 
		printf("bad!\n"); 
	} 
} 

int main(int argc, char *argv[]) {

```

上面的程序中 strlen() 返回类型是 size_t ，却被存储在无符号字符串类型 中，任意超过无符号字符串最大上限值（256 字节）的数据都会导致截断异常。当 密码长度为 261 时，截断后值变为 5，成功绕过了 面我们利用溢出漏洞来获得 shell

## 堆

### mmap

`mmap`（建议的映射起始地址，映射的字节数，内存保护权限，内存的共享属性和特殊行为，指定要映射的文件，文件偏移量） 原型：

> void mmap(void*addr,size_t len,int prot,int flags,int fd,off_t offset);

mmap(期望的起始地址，映射的长度，内存保护权限，映射类型与行为标志，文件描述符，文件内的偏移量)

成功时返回映射区域的起始地址指针

mmap 并不会立即分配物理内存。它只是在进程的虚拟地址空间中划出一块区域，并建立与文件的关联（如果是文件映射）。当程序首次访问这块内存时，会触发一个缺页异常，此时内核才会真正地从磁盘加载文件内容或分配物理内存页。

prot权限位计算：

define PROT_READ     0x1   # 二进制 001  可读  
define PROT_WRITE    0x2   # 二进制 010  可写  
define PROT_EXEC     0x4   # 二进制 100  可执行  
从而有:  
0x1 + 0x2 = 0x3 → 可读 + 可写(rw)  
0x1 + 0x4 = 0x5 → 可读 + 可执行(rx)  
0x1 + 0x2 + 0x4 = 0x7 → 可读 + 可写 + 可执行  
​

总结：addr 和 flags 决定“映射在哪、如何共享”，prot 决定“有什么权限”，而 fd、offset 和 length 共同描述“映射文件的哪一部分”。对于匿名内存，后三者就退化为固定值（-1, 0, 长度）

### malloc

`malloc` （要分配的字节数）

> 原型：void *malloc(size_t size)

返回值：

- 成功：返回指向分配内存的指针，内存内容未初始化（可能是垃圾值）。
    
- 失败：返回 NULL，并设置 errno = ENOMEM。

#### 整数溢出示例 —— 回绕和溢出

```c
void vulnerable() {
	size_t len; 
	// int len; 
	char* buf; 
	
	len = read_int_from_network(); 
	buf = malloc(len + 5); 
	read(fd, buf, len); 
	... 
}
```

*这个例子看似避开了缓冲区溢出的问题，但是如果 len 过大， len+5 有可能发 生回绕。比如说，在 x86-32 上，如果 len = 0xFFFFFFFF ，则 len+5 = 0x00000004 ，这时 malloc() 只分配了 4 字节的内存区域，然后在里面写入大 量的数据，缓冲区溢出也就发生了。（如果将 len 声明为有符号 int 类 型， len+5 可能发生溢出）*

### mprotect

原型：

> mprotect(void *addr, size_t len, int prot);

mprotect(起始地址，长度，保护标志)

参数解释：

1. addr：起始地址 要修改权限的内存区域起始虚拟地址。
    

必须页对齐（page-aligned）。页大小通常是 4096 字节，可用 sysconf(_SC_PAGESIZE) 获取。

如果 addr 不是页大小的整数倍，调用直接失败，返回 -1，errno = EINVAL

2. len：长度 要修改的字节数
    

实际生效范围是 [addr, addr + len)，内核会向下对齐 addr、向上对齐 addr + len 到页边界。

len == 0 时调用失败，errno = EINVAL。

3. prot：保护标志 由以下标志位按位或组合：
    

|标志|值|含义|
|---|---|---|
|PROT_NONE|0x0|完全不可访问，任何读写执行都触发 SIGSEGV|
|PROT_READ|0x1|可读|
|PROT_WRITE|0x2|可写|
|PROT_EXEC|0x4|可执行|
|PROT_SEM|0x8|页面可用于原子操作（semaphore）|

常见组合：

- PROT_READ // 0x1 只读
    
- PROT_READ | PROT_WRITE // 0x3 可读写（典型堆/数据段）
    
- PROT_READ | PROT_EXEC // 0x5 可读可执行（代码段）
    
- PROT_READ | PROT_WRITE | PROT_EXEC // 0x7 RWX —— 漏洞利用里的经典值
    
- PROT_NONE // 0x0 守卫页

## 线程

### pthread_create

`pthread_create`（获取新线程ID，指定线程属性，指定线程执行函数，传递参数） 创建并启动一个线程 它的作用是在当前进程中启动一个全新的线程，并让它开始执行你指定的函数。

函数原型：  
int pthread_create(pthread_t *restrict thread,  
                   const pthread_attr_t *restrict attr,  
                   void *(*start_routine)(void *),  
                   void *restrict arg);

thread (输出参数)：这是一个指向 pthread_t 类型变量的指针。函数成功返回时，会将新线程的ID写入这个变量。后续可以用这个ID来操作该线程（例如等待它结束或分离它）

attr (输入参数)：指向一个 pthread_attr_t 结构体的指针，用于指定新线程的属性。最常见的用法是传入 NULL，表示使用默认属性。如果需要自定义（如设置栈大小、分离状态等），需要先用 pthread_attr_init 等函数来初始化这个结构体

start_routine (输入参数)：这是一个函数指针，指向线程将要执行的函数。这个函数必须符合 void *function_name(void _arg) 的签名，即接收一个 void_ 参数并返回一个 void* 值

arg (输入参数)：传递给 start_routine 函数的唯一参数。如果需要传递多个值，可以将其打包成一个结构体，然后将结构体的指针传入。

### pthread_detach

`pthread_detach`（要分离的线程ID） 分离线程，自动回收资源 它的作用是告诉系统，当指定线程终止时，其占用的资源（如栈、线程描述符）可以被自动回收，无需其他线程来“收尸”

函数原型：  
int pthread_detach(pthread_t thread);

参数详解： thread (输入参数)：要设置为分离状态的线程ID。这个ID可以来自 pthread_create 的输出，也可以是当前线程通过 pthread_self() 获取的自身ID

### 核心要点与关联

理解这两个函数，有几个关键的关联点：

线程的“默认可连接（Joinable）”状态：默认情况下（attr 为 NULL），pthread_create 创建的线程是可连接的。这意味着，即使线程运行结束，它的资源也不会被立即释放，必须由另一个线程调用 pthread_join 来等待它结束并回收资源

pthread_detach 的作用：pthread_detach 是将一个可连接线程转换为分离状态的工具。一旦线程被分离，它就不能再被 pthread_join，其资源会在终止时由系统自动回收

在创建时就分离：除了在线程创建后调用 pthread_detach，我们也可以在 pthread_create 之前，通过设置 attr 的分离属性（PTHREAD_CREATE_DETACHED），直接创建一个从一开始就处于分离状态的线程

配对原则：对于每个创建的线程，要么调用 pthread_join，要么调用 pthread_detach（或在创建时设为分离），以确保系统资源能被释放。如果两者都不做，线程的资源会一直保留到进程结束
