## 常规函数

`read`（读什么（从哪儿读），写到哪，写多少）

`write`（往哪写，写什么（从哪写），写多少）

`execve`（binsh，argv（0），envp（0））

`mencpy`（拷贝到哪里，从哪里开始拷贝，拷贝多少字节）`不检查长度`

`fputc`（要写出的字符，目标文件流）

`getrandom`（指向接收随机字节的缓冲区，请求的随机字节数，控制行为的标志位可以是0） 内核真随机，不能预测

## 分配内存

### mmap

`mmap`（建议的映射起始地址，映射的字节数，内存保护权限，内存的共享属性和特殊行为，指定要映射的文件，文件偏移量）
原型：

> void mmap(void*addr,size_t len,int prot,int flags,int fd,off_t offset);

成功时返回映射区域的起始地址指针

mmap 并不会立即分配物理内存。它只是在进程的虚拟地址空间中划出一块区域，并建立与文件的关联（如果是文件映射）。当程序首次访问这块内存时，会触发一个缺页异常，此时内核才会真正地从磁盘加载文件内容或分配物理内存页。

prot权限位计算：

```python
define PROT_READ     0x1   # 二进制 001  可读
define PROT_WRITE    0x2   # 二进制 010  可写
define PROT_EXEC     0x4   # 二进制 100  可执行
从而有:
0x1 | 0x2 = 0x3 → 可读 + 可写(rw)
0x1 | 0x4 = 0x5 → 可读 + 可执行(rx)
0x1 | 0x2 | 0x4 = 0x7 → 可读 + 可写 + 可执行

```

### malloc

`malloc` （要分配的字节数）

原型：void *malloc(size_t size)

返回值：

- 成功：返回指向分配内存的指针，内存内容未初始化（可能是垃圾值）。

- 失败：返回 NULL，并设置 errno = ENOMEM。

程序发布的时候删掉了原来 C 语言的变量名、函数名，IDA 不知道它本来叫啥，就用【前缀 + 内存地址】给它起名字，方便你看汇编、跳转分析

例如：

| byte_ | 1字节全局变量 | 数据段 |
| word_ | 2字节全局变量 | 数据段 |
| dword_ | 4字节全局变量 | 数据段 |
| qword_ | 8字节全局变量 | 数据段 |
| off_ | 指针/地址偏移 | 数据段 |
| asc_ / aXXX | ASCII字符串 | .rodata / 数据段 |
| unk_ | IDA无法识别的原始字节 | 数据段 |
| flt_ | float单精度浮点数（4字节） | 数据段 |
| dbl_ | double双精度浮点数（8字节） | 数据段 |

## 线程

### pthread_create

`pthread_create`（获取新线程ID，指定线程属性，指定线程执行函数，传递参数）
创建并启动一个线程
它的作用是在当前进程中启动一个全新的线程，并让它开始执行你指定的函数。

```c
函数原型：
int pthread_create(pthread_t *restrict thread,
                   const pthread_attr_t *restrict attr,
                   void *(*start_routine)(void *),
                   void *restrict arg);
```

thread (输出参数)：这是一个指向 pthread_t 类型变量的指针。函数成功返回时，会将新线程的ID写入这个变量。后续可以用这个ID来操作该线程（例如等待它结束或分离它）

attr (输入参数)：指向一个 pthread_attr_t 结构体的指针，用于指定新线程的属性。最常见的用法是传入 NULL，表示使用默认属性。如果需要自定义（如设置栈大小、分离状态等），需要先用 pthread_attr_init 等函数来初始化这个结构体

start_routine (输入参数)：这是一个函数指针，指向线程将要执行的函数。这个函数必须符合 void *function_name(void *arg) 的签名，即接收一个 void* 参数并返回一个 void* 值

arg (输入参数)：传递给 start_routine 函数的唯一参数。如果需要传递多个值，可以将其打包成一个结构体，然后将结构体的指针传入。

### pthread_detach

`pthread_detach`（要分离的线程ID）
分离线程，自动回收资源
它的作用是告诉系统，当指定线程终止时，其占用的资源（如栈、线程描述符）可以被自动回收，无需其他线程来“收尸”

```c
函数原型：
int pthread_detach(pthread_t thread);
```

参数详解：
thread (输入参数)：要设置为分离状态的线程ID。这个ID可以来自 pthread_create 的输出，也可以是当前线程通过 pthread_self() 获取的自身ID

### 核心要点与关联

理解这两个函数，有几个关键的关联点：

线程的“默认可连接（Joinable）”状态：默认情况下（attr 为 NULL），pthread_create 创建的线程是可连接的。这意味着，即使线程运行结束，它的资源也不会被立即释放，必须由另一个线程调用 pthread_join 来等待它结束并回收资源

pthread_detach 的作用：pthread_detach 是将一个可连接线程转换为分离状态的工具。一旦线程被分离，它就不能再被 pthread_join，其资源会在终止时由系统自动回收

在创建时就分离：除了在线程创建后调用 pthread_detach，我们也可以在 pthread_create 之前，通过设置 attr 的分离属性（PTHREAD_CREATE_DETACHED），直接创建一个从一开始就处于分离状态的线程

配对原则：对于每个创建的线程，要么调用 pthread_join，要么调用 pthread_detach（或在创建时设为分离），以确保系统资源能被释放。如果两者都不做，线程的资源会一直保留到进程结束
